# EKT Assistant — сайт и интеграция Backend 0.3

Сайт воспроизводит композицию предоставленного референса: навигация слева, чат по центру,
панель корзины справа, четыре подсказки и нижнее поле сообщения. HTML, CSS и нативные
JavaScript-модули; сборка и Node.js не нужны. Все основные действия обращаются к FastAPI.

## Быстрый запуск без ключей

После установки зависимостей backend в `.venv` из корня:

```powershell
python run_demo.py
```

Откройте **http://127.0.0.1:5173**. Скрипт поднимает оба сервера и включает корзину прототипа.
Ctrl+C завершает оба процесса. Порты 5173 и 8000 должны быть свободны.

Скрипт создаёт свежую копию **синтетических** данных в `backend/data/demo-catalog.json`,
импортирует её в отдельную `demo.sqlite3`, устанавливает срок свежести 3600 секунд и
отключает внешние EKT/OpenAI-вызовы для этого процесса. По истечении часа демонстрационный
снимок требует нового запуска. Основная база `catalog.sqlite3` не изменяется.

## Подключение AI и реального каталога

1. Настройте локальный `backend/.env` по корневому README: ключ OpenAI, доступ к EKT,
   `DEMO_CART_ENABLED=true`, для реальных товаров `EKT_LIVE_ENABLED=true`.
2. Импортируйте реальные данные по инструкции backend.
3. Запустите из `backend/`:

   ```powershell
   ..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
   ```

4. Во втором терминале из корня:

   ```powershell
   python -m http.server 5173 --bind 127.0.0.1 --directory frontend
   ```

Адрес API формируется в `api.js` из протокола и имени хоста страницы с портом 8000.
Используйте один hostname: 127.0.0.1 для обоих серверов либо localhost для обоих.
Для другого размещения измените адрес и CORS согласно контракту. Текущий запуск локальный.
Ключи и Basic Auth остаются исключительно на backend; фронтенд не читает `.env`.

## Сессия и корзина

- Создание `/api/chat/sessions`, Bearer только в памяти, `credentials: include`.
- UUID сообщения сохраняется при повторе; `message_id` защищает от повторного вывода.
- Режимы `rules`, `catalog`, `openai` подписаны корректно.
- Форма количества либо сообщение «Добавь 2» создаёт предложение без изменения корзины.
- Показываются прежние/итоговые количество и сумма, цена, валюта, единица, срок и предупреждения.
- `/api/cart/confirm` вызывается только нажатием «Подтвердить» либо явным повтором
  этой же операции после ошибки. Повтор сохраняет пару proposal_id + Idempotency-Key.
- PRICE_CHANGED, STOCK_CHANGED, PROPOSAL_EXPIRED, CART_CHANGED создают новое предложение,
  которое требует нового подтверждения. Повтор не подтверждает его автоматически.
- Изменение количества, удаление и очистка также проходят отдельное подтверждение.
- `/cart` разрешается относительно origin backend; ссылка не содержит токен и использует
  HttpOnly cookie. Панель обновляется после операций и кнопкой обновления.
- Новый диалог требует согласия: сервер удаляет историю и корзину старой сессии.

Это **корзина прототипа**, без оплаты, резерва и заказа на ekt.kz. При перезапуске backend
она очищается. Валюты и единицы не выводятся по догадке. KZT/шт в тестовой корзине задаёт
сервер как условные демонстрационные правила. Пустые сертификаты не трактуются как их отсутствие.

## Файлы

- `index.html`, `styles.css`: адаптивная композиция, светлая/тёмная темы, доступные диалоги.
- `icons.js`: локальные SVG-иконки; отдельного фирменного набора логотипов в материалах не было.
- `api.js`: HTTP, сессия, ошибки, корзина.
- `app.js`: диалог, карточки, предложения, корзина и навигация.
- `tests/browser_smoke.py`: полный сценарий и повторные проверки корзины.
- `tests/layout_states.py`: пять ширин, загрузка, меню, тема, недоступность сервера.

## Проверки и скриншоты

При запущенном `run_demo.py`, установленном Microsoft Edge и `playwright==1.63.0` в `.venv`:

```powershell
.\.venv\Scripts\python.exe frontend/tests/browser_smoke.py
.\.venv\Scripts\python.exe frontend/tests/layout_states.py
```

Первый тест временно меняет только синтетический товар в `backend/data/demo.sqlite3`,
чтобы воспроизвести изменение цены/остатка, и восстанавливает его через `finally`.
Не запускайте этот тест против реальной базы. Используются отдельные браузерные сессии.

Скриншоты: `test-results/desktop-home.png`, `desktop-confirmation.png`, `desktop-cart.png`,
`mobile-home.png`, `mobile-chat.png`, `mobile-confirmation.png`, `mobile-cart.png`,
`mobile-keyboard.png`, `desktop-loading.png`, `desktop-offline.png`.
