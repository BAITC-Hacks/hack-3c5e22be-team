# EKT Assistant — интерфейс Backend 0.3

Сохранена композиция сайта: навигация слева, чат по центру, корзина справа.
HTML, CSS и нативные JavaScript-модули; Node.js и сборка не нужны.

## Запуск

Установите зависимости по корневому README и из корня выполните:

```powershell
.\.venv\Scripts\python.exe run_demo.py
```

Откройте `http://127.0.0.1:5173`. **Один FastAPI-сервис** обслуживает интерфейс, `/api/*` и `/cart`.
В этом режиме три синтетических товара, отдельная `backend/data/demo.sqlite3`, без внешних
EKT/OpenAI-вызовов. Снимок действует час; перезапуск обновляет его. Ctrl+C останавливает сервис.

Для OpenAI/реальных данных настройте `backend/.env` по корневому README, импортируйте
каталог и запустите `python ../run_server.py` из `backend/` в активном виртуальном окружении.
Адрес по умолчанию `http://127.0.0.1:8000`; отдельный HTTP-сервер frontend не требуется.
Production использует относительные URL того же HTTPS origin; порт 8000 в клиенте не зашит.
Ключи и EKT Basic Auth остаются только на сервере. [Внешний стенд](../docs/deployment.md).

## Контракт и поведение

- `credentials: include`; Bearer только в памяти, `/cart` открывается по HttpOnly cookie.
- UUID сообщения сохраняется при повторе; `message_id` защищает от повторного вывода.
- Режимы `rules`, `catalog`, `openai` отображаются отдельно.
- Количество создаёт предложение: прежнее/итоговое количество и сумма, цена, валюта,
  единица, срок и предупреждения. До подтверждения изменений нет.
- Подтверждение сохраняет `proposal_id` и `Idempotency-Key` при повторе после ошибки.
- PRICE_CHANGED, STOCK_CHANGED, PROPOSAL_EXPIRED, CART_CHANGED требуют нового предложения
  и нового подтверждения. Изменение количества, удаление и очистка также подтверждаются.
- `/cart` не содержит токен; показывает текущее состояние этой сессии.
- Повторное открытие вкладки продолжает действующую cookie-сессию без продления TTL.
- Новый диалог завершает прежнюю серверную сессию и её корзину после согласия пользователя;
  другие вкладки этой сессии получают SESSION_EXPIRED. Разные браузерные профили изолированы.

Это **корзина прототипа**, без оплаты, резерва и заказа на ekt.kz. При перезапуске она очищается.
KZT/шт в тестовой корзине — условные правила; реальные валюты/единицы не выдумываются.
Пустые сертификаты не трактуются как их отсутствие.

## Браузерные проверки

При запущенном `run_demo.py`, установленном Edge и `playwright==1.63.0`:

```powershell
.\.venv\Scripts\python.exe frontend/tests/browser_smoke.py
.\.venv\Scripts\python.exe frontend/tests/layout_states.py
```

Первый тест меняет только синтетический товар в `backend/data/demo.sqlite3`, чтобы
воспроизвести изменение цены/остатка, и восстанавливает его через `finally`.
Не запускайте против реальной базы. Пять размеров экрана и состояния описаны в исходном
`docs/site-qa.md`; повторная приёмка интеграции — в `docs/final-qa.md`.
