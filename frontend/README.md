# Интерфейс участника 2

Адаптивный интерфейс консультации, подключённый к `codex/backend-ai` через REST API.
Нативные JavaScript-модули, HTML и CSS: сборщик и Node.js для запуска не нужны.
Используется действующий контракт `docs/backend-api.md`, а не ранний черновик.

## Запуск

1. Из корня выполните подготовку Python-окружения, установку зависимостей и импорт
   `backend/examples/demo_catalog.json` по корневому README. Ключи не требуются.
2. В первом терминале из `backend/` запустите:

   ```powershell
   ..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
   ```

3. Во втором терминале из корня:

   ```powershell
   python -m http.server 5173 --bind 127.0.0.1 --directory frontend
   ```

4. Откройте http://127.0.0.1:5173. Не открывайте HTML через `file://`.

API по умолчанию: `http://127.0.0.1:8000` (константа в `api.js`). Backend уже разрешает
этот origin фронтенда. При смене адресов согласуйте CORS. Запуск предназначен для
локальной разработки, не для публикации в интернете.

## Реализовано

- Чат с серверным контекстом, поиском, уточнениями и отображением режима `rules/openai`.
- Карточки с ценой, общим остатком, характеристиками, складами, временем снимка.
- Отдельные пометки синтетических и устаревших данных, конфликтов и неизвестных полей.
- Сравнение кандидатов через `/api/products/{id}/alternatives`, причины и необходимость проверки.
- Загрузка, ошибки, ручной повтор, отсутствие параллельных действий, новый диалог.
- При 401 требуется новый диалог: контекстный вопрос не повторяется в пустой сессии автоматически.
- Ссылки только HTTP(S); серверный текст вставляется через `textContent`, без исполнения HTML.
- Bearer-токен только в памяти адаптера: не в localStorage, URL или исходниках.

Корзина, выбор количества с подтверждением, загрузка вложений и проверенные условия покупки
ожидают серверной интеграции. Интерфейс не имитирует успешное добавление. Сертификаты
показываются только по предоставленным ссылкам; статус неизвестного источника виден отдельно.

## Проверка сценария

1. `DEMO-002` → карточка тестового товара. `А какие характеристики?` → тот же товар.
2. Новый диалог, `DEMO-001` → нулевой остаток и кандидат в аналоги.
3. `DEMO-003` → конфликт характеристик; «Сравнить кандидатов» показывает предупреждение.
4. `Добавь в корзину` → явное сообщение, что ничего не добавлено.
5. Вопрос о доставке → ограничения непроверенных условий.
6. Остановить backend и отправить вопрос → ошибка с ручным повтором.
7. Проверить ширину 390 px и клавиатурную навигацию.

История интерфейса существует до перезагрузки страницы или нажатия «Новый диалог».
Последнее действие удаляет контекст на сервере; при сетевой ошибке сброс не считается успешным.

## Автоматическая браузерная проверка

При запущенных серверах из корня, после установки `playwright==1.63.0` в `.venv`:

```powershell
# Если установлен Microsoft Edge:
$env:BROWSER_CHANNEL = 'msedge'
.\.venv\Scripts\python.exe frontend/tests/browser_smoke.py
```

Либо установите Chromium командой `.\.venv\Scripts\python.exe -m playwright install chromium`
и запускайте без переменной `BROWSER_CHANNEL`. Скриншоты сохраняются в `test-results/`,
исключённой из Git. Проверяются контекст, аналоги, конфликты, отсутствие добавления в
корзину, условия, ошибка сети и повтор, истечение сессии, мобильная ширина и безопасный
вывод текста. Проверено локально через Edge; ключи OpenAI и ekt.kz не использовались.
