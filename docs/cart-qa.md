## Что проверяют автоматические тесты

- Нет изменений до отдельного подтверждения; текст чата не является подтверждением.
- Цена берётся с сервера, клиент не может передать свою; неизвестные валюта и единицы не выдумываются.
- Остаток проверяется с учётом уже находящегося в корзине количества.
- Изменение цены/остатка требует нового предложения и нового подтверждения.
- Повтор одного подтверждения не дублирует запись; чужой ключ/предложение отклоняются.
- Параллельные подтверждения сериализованы; успешная операция одна.
- Отзыв/истечение сессии и истечение предложения во время ожидания EKT блокируют запись.
- При ошибке EKT нет успешного ответа на устаревших данных; неизвестные/некорректные поля отклоняются.
- Нулевой остаток, конфликт характеристик, просроченные снимки, превышение количества.
- Нельзя смешивать синтетические и реальные товары.
- Изменение количества, удаление и очистка также требуют подтверждения; отмена сохраняет позиции.
- Удаление работает при недоступности каталога.
- Изоляция сессий, cookie без токена в URL, Bearer-only публичный API.
- Для изменения через страницу нужны cookie, CSRF-токен и совпадающий Origin.
- HTML экранируется, ответы не кэшируются, CORS ограничен, есть лимит операций.
- Старые проверки каталога, поиска, AI, условий покупки и импорта сохранены.

## Найдено и исправлено при интеграции

1. Базовая корзина принимала только синтетические товары; добавлены реальные товары с двумя
   чтениями карточки EKT — при предложении и при подтверждении.
2. Не было изменения/удаления/очистки и связи предложений с чатом — теперь есть.
3. Прежние проверки истечения снимка пытались перезаписать его старым ответом, который новый
   Catalog правильно игнорирует. Тесты изменены так, чтобы моделировать реальное истечение.
4. Пустой список properties ошибочно принимался нормализатором за пустой словарь; теперь тип проверяется.
5. Стандартный prompt ввода количества не поддерживался встроенным браузером. Заменён формой
   на странице; браузерный сценарий после исправления пройден.
6. Изменения после сетевого ожидания повторно проверяют сессию и срок предложения.

## Повторный запуск

Из `backend/`:

```powershell
..\.venv\Scripts\python.exe -m pytest -q
..\.venv\Scripts\python.exe -m ruff check .
..\.venv\Scripts\python.exe -m ruff format --check .
..\.venv\Scripts\python.exe -m pip check
# Запущенный Backend, доступ к EKT, загруженный товар 515292 и включённая корзина:
..\.venv\Scripts\python.exe -X utf8 scripts/check_cart_live.py
# Реальная выборка и OpenAI, снимок условий покупки:
..\.venv\Scripts\python.exe -X utf8 scripts/check_live.py
```

Живые проверки расходуют OpenAI API. Они меняют только локальную тестовую корзину и удаляют
свои сессии. Отчёты в data/ не содержат токенов и не коммитятся.

## Оставшиеся ограничения

- Это корзина приложения, не корзина ekt.kz. Заказ, оплата, синхронизация с магазином отсутствуют.
- Общий quantity не доказывает доступность отгрузки; реальные единицы, кратность и правила складов
  не подтверждены. Поддерживаются целые количества; сумма реальных товаров без выдуманной валюты.
- Нет межсессионного резерва остатков; корзина хранит цену подтверждения, не постоянно текущую цену.
- Сессии/корзины/идемпотентность в памяти одного процесса: TTL или перезапуск очищает доступ.
- Ссылка привязана к браузерной cookie. Между вкладками одного профиля одна активная cookie-сессия.
- UI участника 2 ещё не подключён к новым маршрутам. Проверена отдельная готовая страница /cart,
  а не сквозной сценарий ветки frontend. Нужны credentials: include и обработчики подтверждения.
- Нет проверки публичного развёртывания, нагрузки, всех устройств, сертификатов и вложений.
