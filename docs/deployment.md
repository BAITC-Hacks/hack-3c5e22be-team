# Развёртывание EKT AI

**Статус:** хостинг ещё не выбран, доступ к аккаунту команды не получен, внешнего URL нет.
Подготовлена переносимая конфигурация одного Python/FastAPI-сервиса. Наличие Dockerfile
не означает успешную сборку или публикацию. Фактические проверки и проверенный коммит
фиксируются в [final-qa.md](final-qa.md). Локальный `127.0.0.1` не считается внешним стендом.

## Один сервис и один origin

FastAPI обслуживает frontend и API по одному HTTPS-origin:

| Путь | Назначение |
| --- | --- |
| `/` | Готовый frontend |
| `/styles.css`, `/api.js`, `/app.js`, `/icons.js` | Явно разрешённые файлы frontend |
| `/api/*` | Каталог, чат и Bearer API корзины |
| `/cart`, `/cart/*` | Страница корзины текущей сессии и её операции |
| `/health` | Проверка доступности процесса |
| `/demo-login` | Повторный вход в защищённое публичное демо |

Frontend использует относительные API-запросы и `credentials: include`. Отдельный
frontend-сервер, Node.js и сборщик для этой версии не нужны. Нет общего SPA fallback,
который мог бы перехватить неизвестные `/api` или `/cart` маршруты. Путь frontend
определяется относительно файлов приложения, а не случайной рабочей директории.

Запускать **один worker и одну реплику**, без автоматического горизонтального
масштабирования. Сессии, корзины, предложения и защита повторов находятся в памяти
одного процесса. SQLite хранит каталог, но не сохраняет корзины при перезапуске.

## Локальная проверка Docker

Из корня репозитория, при установленном Docker с Compose:

```shell
docker compose up --build -d
docker compose logs web
```

После запуска открыть `http://127.0.0.1:5173/` и `/health` на том же origin.
Это команды запуска, а не заявление, что Docker уже проверен в текущем окружении.

Текущий `compose.yaml` привязывает порт только к loopback, отключает внешние EKT/OpenAI
вызовы и публичный режим. Он создаёт свежие синтетические данные в отдельной
`/app/backend/data/demo.sqlite3`, включает корзину прототипа и использует срок свежести
снимка 86400 секунд. `catalog` — именованный volume каталога. Остановка через
`docker compose down` сохраняет volume; `down -v` удалит его данные.

Для локального HTTP `CART_COOKIE_SECURE=false`. Публично размещать эту конфигурацию
без изменения настроек HTTPS и входного контроля нельзя.

## Параметры сервиса на выбранном хостинге

Dockerfile использует Python 3.12, устанавливает `backend/requirements.lock` и пакет
backend, копирует frontend в образ. Сервис работает от пользователя UID 10001.
Рабочая директория контейнера — `/app/backend`, команда — `python /app/run_server.py`.
Порт по умолчанию 8000; платформа может передать `PORT` через окружение процесса.
Healthcheck обращается к `/health` на этом порту. Постоянный диск монтируется в
`/app/backend/data`; пользователь UID 10001 должен иметь право записи.

Если выбранный хостинг запускает исходники без Docker, команды установки из корня:

```shell
python -m pip install -r backend/requirements.lock
python -m pip install --no-deps -e ./backend
```

Затем рабочая директория `backend/`, команда запуска:

```shell
python ../run_server.py
```

В окружении процесса укажите реальный порт платформы. Этот launcher слушает
`0.0.0.0` и явно задаёт `workers=1`. Для локального синтетического показа предназначен
`python run_demo.py` из корня, а не команда публичного сервиса.

## Обязательные настройки публичного HTTPS-демо

Задайте значения в настройках сервиса выбранного хостинга. Пароли и API-ключи храните
только в его secret settings, не в репозитории, frontend, Dockerfile или аргументах
команд. `.dockerignore` исключает `.env` и локальную папку данных из образа.

| Переменная | Настройка |
| --- | --- |
| `PUBLIC_DEMO` | `true`, явно включает общий входной контроль и лимиты |
| `PUBLIC_DEMO_USERNAME`, `PUBLIC_DEMO_PASSWORD` | Непустые отдельные учётные данные демо в secret settings; имя без двоеточия |
| `PUBLIC_DEMO_COOKIE_SECURE` | `true`; отключение запрещает запуск публичного режима |
| `CART_COOKIE_SECURE` | `true` за HTTPS |
| `TRUSTED_PROXY_IPS` | Конкретный доверенный IP/список IP или подсеть реального proxy выбранной платформы, никогда `*` |
| `PORT` | Порт, который выделяет платформа; default Dockerfile — 8000 |
| `DEMO_CART_ENABLED` | `true`, включает отдельную корзину прототипа |
| `CORS_ORIGINS` | `[]` при едином origin; если нужен отдельный разрешённый origin, укажите его точным JSON-списком без wildcard |
| `CATALOG_DB` | Абсолютный путь на постоянном диске; синтетический и реальный каталоги держать в разных SQLite-файлах |
| `PURCHASE_TERMS_PATH` | Абсолютный путь к актуальному проверенному снимку условий |

**`PORT`, `TRUSTED_PROXY_IPS` и `DEMO_SEED_SYNTHETIC` читает launcher непосредственно
из окружения процесса. Записи только в `backend/.env` для них не работают.** Остальные
настройки читает `Settings`; при запуске из `backend/` он также может читать локальный
`.env`, но на хостинге используйте окружение и secret settings.

Прокси должен сохранить публичный `Host` и корректно передать HTTPS-схему.
Launcher доверяет forwarded headers только адресам из `TRUSTED_PROXY_IPS`.
Не подставляйте `127.0.0.1`, если фактический proxy находится по другому адресу.
При неверном proxy/Host приложение может видеть HTTP или другой origin: создание
сессии и операции `/cart/*` завершатся `403 ORIGIN_FORBIDDEN` или `403 CSRF_INVALID`.
Настройка `CART_COOKIE_SECURE=true` сама по себе не исправляет origin. Проверяйте это
через конечный HTTPS-URL; не отключайте CSRF-проверку ради обхода ошибки.

Первое открытие сайта запрашивает HTTP Basic вход. После входа сервер выдаёт отдельную
подписанную HttpOnly Secure cookie `__Host-ekt_demo_access`. Она позволяет Bearer-токену
чата продолжать занимать заголовок Authorization. По истечении cookie войдите снова
через `/demo-login`. Без входа `/health` возвращает только `{"status":"ok"}`; это
проверка доступности, а не подтверждение наличия каталога или работоспособности корзины.

## Лимиты и срок жизни

| Переменная | По умолчанию | Что ограничивает |
| --- | --- | --- |
| `PUBLIC_DEMO_REQUESTS_PER_MINUTE` | 120 | Суммарные допущенные запросы `/api`, `/api/*`, `/cart`, `/cart/*` всех посетителей за минуту |
| `PUBLIC_DEMO_MAX_REQUESTS` | 1000 | Общий бюджет таких запросов на время жизни процесса |
| `PUBLIC_DEMO_MAX_BODY_BYTES` | 65536 | Размер тела запроса до выполнения API-операции |
| `PUBLIC_DEMO_COOKIE_TTL_SECONDS` | 28800 | Срок cookie доступа к демо, 8 часов |
| `SESSION_TTL_SECONDS` | 3600 | Срок сессии чата и корзины от создания, 1 час |
| `MAX_SESSIONS` | 1000 | Одновременно хранимые сессии |
| `CHAT_REQUESTS_PER_MINUTE` | 30 | Сообщения одной сессии |
| `CART_REQUESTS_PER_MINUTE` | 60 | Запросы изменения корзины одной сессии |
| `CART_PROPOSAL_TTL_SECONDS` | 300 | Срок предложения, 5 минут |

Глобальный лимит охватывает также создание новых сессий. Статика и вход в него не входят.
Это бюджет количества запросов, а не денежный лимит OpenAI. После исчерпания общего
бюджета возвращается `429 DEMO_BUDGET_EXHAUSTED`; минутного — `429 DEMO_RATE_LIMITED`.
Выберите значения под продолжительность показа и установите доступные ограничения
расходов в аккаунте AI-провайдера, если подключаете платную модель.

**При рестарте обнуляются бюджеты запросов и меняется ключ cookie входа. Также
теряются сессии, корзины и ключи повторов.** Постоянный SQLite volume этого не меняет.
Текущий ограничитель рассчитан на один процесс и не является устойчивым бюджетом
расходов между перезапусками или несколькими репликами.

## Каталог и условия

Для первого внешнего показа без доступов партнёра используйте синтетический режим:
`DEMO_SEED_SYNTHETIC=true`, `EKT_LIVE_ENABLED=false`, пустой `OPENAI_API_KEY` и отдельный
`CATALOG_DB=/app/backend/data/demo.sqlite3`. Укажите `CATALOG_STALE_SECONDS=86400`, как
в Compose, либо другой явно согласованный срок демонстрации. При каждом старте launcher
обновляет время только синтетического примера. Он откажется заполнять базу с реальными
товарами или работать с seed при включённом EKT live. Этот приём нельзя использовать
для искусственного «освежения» реальных остатков.

Для реального каталога сначала получить доступ партнёра. Установить
`DEMO_SEED_SYNTHETIC=false`, отдельный `CATALOG_DB`, секреты `EKT_USERNAME` и
`EKT_PASSWORD`. Только после настройки доступа включать `EKT_LIVE_ENABLED=true`.
`OPENAI_API_KEY` подключается независимо и только при наличии разрешённого аккаунта.
Без AI-ключа работает честный резервный режим.

Ограниченный импорт из `backend/` в том же окружении и на тот же диск:

```shell
python -m app.import_catalog --pages 6 --max-details 100 --concurrency 2 --timeout 10 --report data/import-report.json
```

Команда читает до 6 страниц и до 100 подробных карточек; не заменяйте её полной выгрузкой
без согласования. Частичный импорт возвращает код 2 и записывает ошибки в отчёт.
Проверьте отчёт и карточки перед показом. Реальная SQLite-база исключена из Git и не
попадёт на хостинг сама. При эфемерном диске требуется повторять этот импорт при каждом
развёртывании до начала приёмки и сохранять план восстановления. Предпочтителен
постоянный volume с отдельным реальным файлом каталога.

Для синтетического сценария используйте DEMO-001 и DEMO-002 с явной тестовой пометкой.
По истечении срока свежести снимка добавление блокируется. Обычный повторный импорт
старого файла не делает данные свежими: импортёр сохраняет время изменения файла.

В Compose подключён `backend/examples/purchase_terms.ekt.json`, проверенный 23.09.2026
со сроком до 23.10.2026. На хостинге можно указать этот файл или скопировать согласованный
снимок в постоянные данные и задать `PURCHASE_TERMS_PATH`. После обновления файла
перезапустите сервис: условия читаются при старте. Истёкшие условия требуют новой
проверки источника. Неизвестную кратность и противоречивые пороги доставки не подменять
догадками.

## Что нужно для публикации и приёмки

До публикации требуются конкретные аккаунт и проект хостинга команды, право создать
сервис и задать секреты, информация об HTTPS-proxy, постоянный диск либо согласованный
повторный импорт. Платформа, URL, команды платформы и идентификатор развёртывания
появятся здесь после получения доступа. Сейчас этих подтверждений нет.

Развернуть выбранный коммит из GitHub и проверить конечный HTTPS-URL в другом браузере
или на другом устройстве. Через сайт пройти поиск, предложение с пустой корзиной до
подтверждения, подтверждение, актуальную `/cart`, повтор без удвоения, изменение,
отмену и удаление. Отдельно проверить две независимые сессии, ошибку API, мобильную
ширину около 390 px и отсутствие запросов к localhost, CORS/cookie/HTTPS ошибок.
Записать фактические результаты, URL и тот же SHA коммита в `docs/final-qa.md`.

Прототип не резервирует товар в EKT, не оформляет заказ и не принимает оплату.
