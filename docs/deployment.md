# Эксплуатация раннего стенда

Текущий объём — локальный Docker Compose и временный контейнер в CI. Постоянного URL, облачного сервиса и автоматической публикации нет.

## Проверка запуска

1. Установить Node.js 24.x или Docker с Compose v2.
2. Выполнить `npm run check` или `docker compose up --build -d --wait --wait-timeout 90`.
3. Открыть `/` и `/healthz` на порту 3000. Ожидается 200; `/api/status` показывает отключённые интеграции.
4. Проверить `docker compose ps` и логи. Для остановки выполнить `docker compose down`.

Если порт занят, задать другой `PORT` в `.env`. Если контейнер нездоров, проверить `docker compose logs app`; не считать успешную сборку успешным запуском. Если нет доступа к Docker Hub, образ не соберётся — требуется сетевой доступ к реестру.

## Перед внешним размещением

- Определить провайдера, владельца окружения и бюджет.
- Настроить HTTPS и ограничить доступ к тестовому стенду.
- Закрепить образ по digest и сохранять идентификатор релиза/commit.
- Хранить ключи вне Git; определить сроки хранения и маскирование журналов.
- Добавить readiness реальных зависимостей отдельно от `/healthz`.
- Проверить восстановление и откат на предыдущий образ. Текущий сервис не хранит данные; после появления БД потребуется план миграций и резервирования.
- Пройти бизнес-приёмку до подключения к реальной корзине.

Текущая политика `frame-ancestors 'none'` запрещает iframe. При выборе способа встраивания чата отдельно согласовать допустимый origin ekt.kz, сессии и защиту запросов. Не снимать ограничения глобально.
