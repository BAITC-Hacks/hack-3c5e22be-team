## QA-001 — интерфейс не подключён к API корзины

Версии: frontend `b88313f`, cart `df8c66d`. Создать сессию, запросить DEMO-002, написать
«Да, добавь 2 DEMO-002 в корзину». Нет выбора количества, карточки предложения, кнопки
подтверждения и cart_url; показано «Товары не добавлены». `frontend/api.js` не содержит
методов корзины, fetch использует `credentials: 'omit'`.

Ожидание: UI создаёт предложение, показывает состав/сумму, после отдельного подтверждения
вызывает confirm с постоянным ключом повтора и открывает актуальную корзину того же пользователя.
Cookie-навигация требует `credentials: 'include'` и origin Backend для относительной ссылки.

Закрыть: browser E2E на desktop и mobile; до подтверждения корзина пуста, после содержит
ровно выбранное количество, повтор не дублирует, ссылка показывает актуальные данные,
другая сессия не видит корзину; ошибки цены/остатка/401 показаны без ложного успеха.

## QA-002 — условия покупки отсутствуют

В работающем UI спросить оплату, доставку и минимальную партию. Ответ — перенаправление к
менеджеру; `/api/purchase-terms` возвращает `verified:false`, поля условий пустые.
Это корректный безопасный fallback, но не выполнение must-have содержательного ответа.

Закрыть: партнёр предоставляет утверждённые правила и источник; Backend подключает их;
тесты проверяют каждый вид условий, зависимость от контекста и минимум одно исключение.
Синтетические условия допустимы только с явной пометкой демо и согласованным объёмом приёмки.

## QA-003 — повторный импорт не восстанавливает демо

`import_files` использует mtime файла как `observed_at`. В README/cart-api сказано повторить
импорт при устаревании, однако mtime при этом не меняется. Файл старше 300 секунд → импорт
→ повторный импорт → POST proposal DEMO-002 quantity=1 → 503 CATALOG_UNAVAILABLE.

Ожидание: документированный путь подготовки синтетического демо действительно даёт пригодный
fixture. Не разрешается просто выдавать старый реальный снимок за свежий.

Воспроизведение: `python -m pytest qa -k qa003 -v`.
Закрыть: отдельная явная подготовка/генерация синтетических fixture либо исправленная
инструкция с проверяемой политикой времени; тест проходит для старого файла. Регрессия:
старый `ekt_api` снимок остаётся устаревшим после импорта.

## QA-004 — сверхбольшой ID приводит к 500

GET `/api/products/1267650600228229401496703205376` и POST `/api/cart/proposals`
с тем же `product_id`, quantity=1, валидной сессией → 500 Internal Server Error.
Причина по коду: Python int без верхней границы передаётся в SQLite signed INTEGER.

Ожидание: 422 либо 404, без 500 и без изменения корзины. Воспроизведение:
`python -m pytest qa -k qa004 -v`. Проверить также отрицательные и предельные ID.
Закрыть: согласованный диапазон ID валидируется на HTTP-границе и безопасно обрабатывается
каталогом; оба падающих теста и регрессия проходят.

## QA-005 — сертификат с источником нельзя проверить

Карточка сообщает «Источник сертификатов не подключён». Нормализация всегда выдаёт
`certificates=[]`, `certificate_status=unknown`; положительного fixture/сопоставления
документа с артикулом нет. Это не утверждение, что у товара отсутствует сертификат,
и не дефект конкретного неизвестного формата API — это пробел в данных и реализации.

Закрыть: согласованный источник и тестовый товар с документом; ссылка доступна и относится
именно к этому товару. Проверить также товар без документа. Пока нельзя засчитать условную
ветку must-have «если сертификат есть в базе — вернуть ссылку».

## QA-006 — изменения разнесены по веткам

На момент прогона `main` содержит только README и frontend-контракт. Каркас Node находится
в `chore/bootstrap-environment`, FastAPI — в `codex/backend-ai`, UI — в
`codex/frontend-chat`, корзина — в `feat/demo-cart`. Общего проверенного checkout нет.
Для QA frontend и cart Backend запущены из двух отдельных снимков; консультации соединяются.

Закрыть: согласованная общая ветка, единый README и команды запуска; чистое окружение
воспроизводит M1–M5. Определить, что запускается/деплоится — каркас Node или итоговый FastAPI
с UI. Это не поручение автоматически сливать текущие PR.

## QA-007 — GitHub CI не выполняет шаги

[Запуск](https://github.com/BAITC-Hacks/hack-3c5e22be-team/actions/runs/35851753746)
имеет conclusion=failure, job backend, steps=[]. Логи шагов отсутствуют. Причина
через текущий доступ не установлена; не приписываем ошибку оплате/лимитам без доказательств.

Закрыть: владелец открывает диагностическое сообщение запуска, устраняет причину;
новый run выполняет установку, lint и тесты и завершается success на сдаваемом commit.
Локальные 61 PASS остаются отдельным доказательством, не заменяют этот результат.
