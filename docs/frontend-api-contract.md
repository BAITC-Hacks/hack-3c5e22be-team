# Контракт Frontend ↔ Backend — черновик для согласования

Это предложение участника 2, а не описание существующего API. Стек и пути можно адаптировать к реализации участника 1. До подключения сервера интерфейс использует синтетические данные с видимой пометкой «Демо: тестовые данные».

## Границы ответственности

- Участник 2: чат, карточки, сравнение аналогов, количество, подтверждение, ошибки и мобильная версия.
- Участник 1: диалог, каталог, достоверность цены и наличия, подбор аналогов, создание предложения для подтверждения.
- Участники 1 и 3: серверная проверка предложения, сессий, остатков и изменение корзины.
- Basic Auth каталога используется только сервером. Его учётные данные не передаются браузеру, не включаются в исходники и сообщения ИИ.

## Предлагаемые запросы

| Метод и путь | Запрос | Ответ |
| --- | --- | --- |
| POST /api/chat | `{ "message": "Нужен автомат", "request_id": "uuid" }` | Сообщение ассистента и карточки |
| POST /api/cart/proposals | `{ "product_id": "demo-1", "quantity": 2 }` | Зафиксированное предложение с ценой, количеством и сроком действия; корзина не меняется |
| POST /api/cart/confirm | `{ "proposal_id": "opaque-id" }`, заголовок `Idempotency-Key` | Результат добавления и ссылка на актуальную корзину |
| GET /api/cart | — | Корзина текущей сессии |

Сессию определяет сервер. Предпочтительный вариант при одном origin — HttpOnly cookie с Secure в HTTPS и SameSite=Lax; изменяющие запросы требуют серверной защиты от CSRF. Если фронтенд и сервер размещены отдельно, механизм cookie, CORS и CSRF согласуется до подключения. ID корзины или предложения сам по себе не даёт права доступа.

## Формат ответа чата

```json
{
  "message_id": "msg-1",
  "text": "Найден тестовый товар.",
  "data_mode": "demo",
  "products": [
    {
      "id": "demo-1",
      "sku": "DEMO-001",
      "name": "Тестовый автоматический выключатель",
      "price": { "amount": "1500.00", "currency": "KZT" },
      "unit": "шт",
      "availability": "in_stock",
      "available_quantity": 10,
      "quantity_rules": { "min": 1, "step": 1 },
      "attributes": [{ "name": "Номинальный ток", "value": "16 А" }],
      "certificates": [],
      "image_url": null,
      "product_url": null,
      "checked_at": null,
      "warnings": []
    }
  ],
  "alternatives": [],
  "sources": []
}
```

Все значения в примере синтетические. Неизвестные цена, остаток и правила количества передаются как `null`, а не как ноль. `availability`: `in_stock`, `out_of_stock`, `unknown`. `data_mode`: `demo` или `live`. `checked_at` — время проверки ISO 8601 либо `null`.

Элемент `alternatives`: `{ "product": "объект товара той же структуры", "reason": "обоснование", "differences": ["отличие"] }`. В реальном JSON поле `product` содержит объект, не строку. Сертификат: `{ "title": "Название", "url": "https://..." }`. Источник: `{ "title": "Название", "url": "https://..." }`. Пустой список сертификатов показывается как «Сертификат не предоставлен».

## Предложение и подтверждение

Ответ создания предложения: `proposal_id`, `product_id`, `name`, `quantity`, `unit`, `unit_price`, `total`, `currency`, `expires_at`. Денежные значения — десятичные строки. Сервер хранит и связывает предложение с сессией; не доверяет цене из браузера.

1. Выбор товара и количества создаёт предложение, но не добавляет товар.
2. Пользователь видит товар, количество, единицу, цену и сумму и нажимает «Подтвердить добавление».
3. На время запроса кнопка блокируется. Повтор запроса использует тот же ключ идемпотентности; сервер исключает повторное добавление.
4. Сервер проверяет сессию, срок предложения, цену, допустимые склады и остаток с учётом количества уже в корзине.
5. При изменении цены или доступного количества требуется новое предложение и новое подтверждение. При недоступности проверки успех не показывается.
6. После подтверждённого успеха сервер возвращает `cart_url` и актуальную корзину. Ссылка сама по себе не должна предоставлять доступ к чужой корзине.
7. Изменение выбора или отмена скрывает старое подтверждение. Использованное предложение нельзя применить повторно.

## Ошибки и состояния интерфейса

Формат ошибки: `{ "error": { "code": "STOCK_CHANGED", "message": "Наличие изменилось", "retryable": false } }`.

Минимальные коды: `VALIDATION_ERROR`, `STOCK_CHANGED`, `PRICE_CHANGED`, `PROPOSAL_EXPIRED`, `CATALOG_UNAVAILABLE`, `SESSION_EXPIRED`, `DATA_CONFLICT`.

Нужны состояния: ожидание ответа, пустой результат, уточняющий вопрос, конфликт характеристик, неизвестное наличие, ошибка сети, проверка перед добавлением, успешное добавление. После сетевого сбоя подтверждения статус операции уточняется либо запрос повторяется с прежним ключом; новое независимое добавление автоматически не запускается.
