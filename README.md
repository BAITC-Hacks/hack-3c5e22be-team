## EKT Assistant: Backend и AI

Backend 0.3: консультации по каталогу ekt.kz и рабочая корзина прототипа.

- FastAPI, SQLite и адаптер каталога с Basic Auth.
- Поиск по ID, внутреннему артикулу, артикулу поставщика и словам названия.
- Нормализация карточек и выявление конфликта номинального тока.
- Консервативный подбор кандидатов в аналоги для автоматических выключателей.
- OpenAI Responses API распознаёт намерение; факты в ответе формирует сервер из каталога.
- Контекст диалога внутри изолированной сессии; ограниченный срок хранения в памяти.
- Явные режимы отсутствия ключа, устаревшего снимка и недоступного AI/API.

Корзина прототипа реализована отдельно от корзины ekt.kz. Вложения и встраивание в настоящий сайт ещё не реализованы. Источник сертификатов,
правила продажи со складов и минимальные партии требуют уточнения у партнёра.
Условия оплаты/доставки с официального сайта доступны отдельным проверенным снимком.

### Запуск

Нужен Python 3.11+. Из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.lock
.\.venv\Scripts\python.exe -m pip install --no-deps -e ./backend
cd backend
Copy-Item .env.example .env
```

Заполните `OPENAI_API_KEY` в локальном `backend/.env`. Модель настраивается через
`OPENAI_MODEL`; начальное значение — `gpt-4o-mini`. Доступность модели зависит от аккаунта.
Без ключа работает базовый поиск (`mode: "rules"`). Точные артикулы и выбор результата
по порядку обрабатываются без вызова модели (`mode: "catalog"`).

Чтобы запустить с синтетическими данными (не реальные предложения ekt.kz):

```powershell
..\.venv\Scripts\python.exe -m app.import_catalog --files examples/demo_catalog.json --source synthetic
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте [Swagger UI](http://127.0.0.1:8000/docs) или [health](http://127.0.0.1:8000/health).
В Linux/macOS используйте `.venv/bin/python` вместо `.venv\Scripts\python.exe`.
Все команды приложения выполняются из `backend/`: относительно этой папки читается `.env`.

### Реальные данные

В `.env` заполните `EKT_USERNAME` и `EKT_PASSWORD`. Они используются только сервером.
Не отправляйте ключи в чат, браузерный код и Git.

```powershell
# Репрезентативная выборка: 6 страниц, до 100 подробных карточек.
..\.venv\Scripts\python.exe -m app.import_catalog --pages 6 --max-details 100 --concurrency 2 --timeout 10 --report data/import-report.json
```

Импорт хранит время получения каждой карточки. Ошибки подробных карточек считаются
в `failures`, товары из списка сохраняются с неизвестным остатком. Если список обновился,
он не перезаписывает подробную карточку и не делает старый остаток «свежим».
Повреждённая карточка или недоступная страница не прерывают весь импорт. Отчёт содержит
число ошибок; частичный импорт завершается кодом 2. Старый ответ не перезаписывает более
новый снимок. Параллелизм ограничен 1–4 запросами. Каталог локальный:
`backend/data/catalog.sqlite3` исключён из Git.

`EKT_LIVE_ENABLED=true` разрешает `GET /api/products/{id}?refresh=true` для загруженных товаров.
При ошибке API метод возвращает 503, а не старый остаток под видом актуального.
Приложение не меняет данные ekt.kz и не делает фоновых полных выгрузок.

API не передаёт валюту и единицу измерения в проверенных ответах: их нельзя автоматически
подставлять. Общий `quantity` не означает подтверждённый доступный к продаже остаток:
правила складов требуют уточнения. `KRATNOST_MIN` пока хранится как необработанное значение.

### Архитектура и границы

```text
Frontend → FastAPI → OpenAI (только намерение и краткий контекст)
                 → Catalog / SQLite → карточки и факты для ответа
                 → EktClient (явное обновление, таймаут, только GET)
                 → проверенные условия покупки из локального JSON
```

Модель не генерирует цену и остаток; у неё нет инструмента изменения корзины.
При включённом прототипе чат готовит предложение с `cart_action: "confirmation_required"`.
Товары меняются только через отдельное подтверждение конкретного предложения.
Контракт: [docs/backend-api.md](docs/backend-api.md).

Аналоги сейчас — только кандидаты по совпадающим доступным характеристикам одной категории.
При конфликте или нехватке обязательных характеристик автоматический подбор не выполняется.
Кандидат не равен подтверждению полной электротехнической совместимости.

Для подключения условий скопируйте `examples/purchase_terms.ekt.json` в
`data/purchase_terms.json`. Снимок проверен по официальному сайту 23.09.2026 и действует
до 23.10.2026; после этой даты ответ просит уточнить условия. Несогласованные пороги доставки
отмечены явно. Минимальная партия не выдумывается. Для своих согласованных условий используйте
`examples/purchase_terms.example.json`, укажите источник и установите `verified: true`.

### Корзина прототипа

В локальном `backend/.env` установите `DEMO_CART_ENABLED=true` (в новом .env.example уже включено).
Для реальных товаров нужен `EKT_LIVE_ENABLED=true`: перед предложением и подтверждением сервер
повторно читает карточку EKT. При ошибке добавление блокируется. Прототип не изменяет ekt.kz.

- Добавление, новое количество, удаление, очистка и отмена предложения.
- Отдельное подтверждение, проверка цены/остатка, защита от повторных/параллельных запросов.
- Готовая страница `/cart` с формами и подтверждением; токен не входит в ссылку.
- Реальные данные: валюта и единицы остаются неизвестными. Синтетические товары: явно тестовые KZT/шт.
- Хранение в одной серверной сессии; перезапуск очищает корзины. Один worker.

Фронтенд должен создавать сессию и вызывать API с `credentials: "include"`, сохранять Bearer-токен
в памяти и разрешать `cart_url` относительно Backend. Без browser cookie /cart вернёт 401.
Через Swagger сначала выполните POST /api/chat/sessions, затем откройте /cart в том же браузере.
Готовый контракт с примерами: [docs/cart-api.md](docs/cart-api.md).
Результаты проверки: [docs/cart-qa.md](docs/cart-qa.md).

### Проверки

Из `backend/`:

```powershell
..\.venv\Scripts\python.exe -m pytest -q
..\.venv\Scripts\python.exe -m ruff check .
```

Тесты используют синтетические товары и подменённые ответы OpenAI/ekt.kz.
Они не требуют ключей и не делают внешних запросов. Реальные ключи не входят в тестовые данные.
Зависимости для разработки также описаны в `pyproject.toml` (extra `dev`).

Живая проверка отдельно вызывает запущенный сервер и расходует OpenAI API:

```powershell
..\.venv\Scripts\python.exe -X utf8 scripts/check_live.py --report data/live-check.json
```

Нужны реальная выборка выше, настроенный OpenAI и подключённый снимок условий покупки.
Скрипт проверяет 10 сценариев, удаляет свою сессию, сохраняет результат без токенов.
Итоги проверки и ограничения: [docs/backend-qa.md](docs/backend-qa.md).

### Ограничения прототипа и следующие шаги

1. Получить источник сертификатов, минимальные партии и правила складов.
2. Расширить репрезентативную выборку: в 100 проверенных карточках нет подтверждённой пары
   «нулевой остаток → подходящий доступный аналог» по строгим текущим правилам.
3. Уточнить схему характеристик для других категорий и расширить поисковые сценарии.
4. Участнику 2 подключить API корзины и новые cart_action по [контракту корзины](docs/cart-api.md).
   Базовая страница /cart уже работает. Настоящая корзина EKT требует API партнёра.
5. При публичном развёртывании добавить входной контроль доступа и общий лимит затрат.
   Лимит 30 сообщений в минуту на сессию уже есть, но он не заменяет защиту публичного сервиса.
   Текущий сервер предназначен для локальной командной разработки, запускается на loopback.
   Сессии находятся в памяти одного процесса, теряются после перезапуска; запускать один worker.
   Поиск сканирует небольшую выборку SQLite; это не индекс полного каталога.
