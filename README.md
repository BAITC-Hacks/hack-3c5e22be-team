## EKT Assistant: Backend и AI

Первый этап работы участника 1: API консультаций по каталогу ekt.kz.

- FastAPI, SQLite и адаптер каталога с Basic Auth.
- Поиск по ID, внутреннему артикулу, артикулу поставщика и словам названия.
- Нормализация карточек и выявление конфликта номинального тока.
- Консервативный подбор кандидатов в аналоги для автоматических выключателей.
- OpenAI Responses API распознаёт намерение; факты в ответе формирует сервер из каталога.
- Контекст диалога внутри изолированной сессии; ограниченный срок хранения в памяти.
- Явные режимы отсутствия ключа, устаревшего снимка и недоступного AI/API.

Демонстрационная корзина реализована отдельными маршрутами и включается настройкой
`DEMO_CART_ENABLED=true`. Она принимает только синтетические товары. Вложения,
реальная корзина и интеграция с настоящим сайтом ещё не реализованы. Проверенные условия
покупки и схема сертификатов ожидаются от партнёра. Эти ограничения видны в API и ответах.

### Запуск

Нужен Python 3.11+. Из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.lock
.\.venv\Scripts\python.exe -m pip install --no-deps -e ./backend
cd backend
Copy-Item .env.example .env
```

Заполните `OPENAI_API_KEY` в локальном `backend/.env`. Модель настраивается через
`OPENAI_MODEL`; начальное значение — `gpt-4o-mini`. Доступность модели зависит от аккаунта.
Без ключа работает базовый поиск, в ответе будет `mode: "rules"`.

Чтобы запустить с синтетическими данными (не реальные предложения ekt.kz):

```powershell
..\.venv\Scripts\python.exe -m app.import_catalog --files examples/demo_catalog.json --source synthetic
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте [Swagger UI](http://127.0.0.1:8000/docs) или [health](http://127.0.0.1:8000/health).
В Linux/macOS используйте `.venv/bin/python` вместо `.venv\Scripts\python.exe`.
Все команды приложения выполняются из `backend/`: относительно этой папки читается `.env`.

### Реальные данные

В `.env` заполните `EKT_USERNAME` и `EKT_PASSWORD`. Они используются только сервером.
Не отправляйте ключи в чат, браузерный код и Git.

```powershell
# Ограниченный импорт: 2 страницы, до 40 подробных карточек.
..\.venv\Scripts\python.exe -m app.import_catalog --pages 2 --max-details 40
```

Импорт хранит время получения каждой карточки. Ошибки подробных карточек считаются
в `failures`, товары из списка сохраняются с неизвестным остатком. Если список обновился,
он не перезаписывает подробную карточку и не делает старый остаток «свежим».
Каталог локальный: `backend/data/catalog.sqlite3` исключён из Git.

`EKT_LIVE_ENABLED=true` разрешает `GET /api/products/{id}?refresh=true` для загруженных товаров.
При ошибке API метод возвращает 503, а не старый остаток под видом актуального.
Приложение не меняет данные ekt.kz и не делает фоновых полных выгрузок.

API не передаёт валюту и единицу измерения в проверенных ответах: их нельзя автоматически
подставлять. Общий `quantity` не означает подтверждённый доступный к продаже остаток:
правила складов требуют уточнения. `KRATNOST_MIN` пока хранится как необработанное значение.

### Архитектура и границы

```text
Frontend → FastAPI → OpenAI (только намерение и краткий контекст)
                 → Catalog / SQLite → карточки и факты для ответа
                 → EktClient (явное обновление, таймаут, только GET)
                 → проверенные условия покупки из локального JSON
```

Модель не генерирует цену, остаток или ссылку; у неё нет инструмента изменения корзины.
`cart_action: "integration_required"` — сигнал фронтенду о недоступной интеграции,
а не разрешение выполнить добавление. Даже сообщение «да, добавь» не изменяет корзину.
Контракт: [docs/backend-api.md](docs/backend-api.md).

### Демонстрационная корзина

Установите `DEMO_CART_ENABLED=true` в `backend/.env` и импортируйте синтетический каталог
командой выше. Если снимок устарел (по умолчанию 300 секунд), повторите импорт перед демо.
Запускайте один worker: корзины и сессии хранятся в памяти до истечения TTL или перезапуска.

После создания `/api/chat/sessions` используйте его Bearer-токен для
`POST /api/cart/proposals`, затем после явного подтверждения пользователя —
`POST /api/cart/confirm` с `Idempotency-Key`. Ответ содержит актуальную корзину и `/cart`.
Обычная браузерная ссылка использует HttpOnly cookie этой же сессии; токен не входит в URL.
Фронтенд должен использовать `credentials: 'include'` и разрешать `/cart` относительно
адреса Backend. Текст чата сам по себе ничего не добавляет.

Детальный контракт, пример запроса, ограничения и проверенные сценарии:
[docs/cart-api.md](docs/cart-api.md). Техническая совместимость с Backend проверена тестами;
отдельное согласование участником Backend ещё ожидается.

Аналоги сейчас — только кандидаты по совпадающим доступным характеристикам одной категории.
При конфликте или нехватке обязательных характеристик автоматический подбор не выполняется.
Кандидат не равен подтверждению полной электротехнической совместимости.

Для подключения условий скопируйте `examples/purchase_terms.example.json` в
`data/purchase_terms.json`, добавьте согласованный текст и источник, затем установите
`verified: true`. Без проверки ассистент направляет за уточнением к менеджеру.

### Проверки

Из `backend/`:

```powershell
..\.venv\Scripts\python.exe -m pytest -q
..\.venv\Scripts\python.exe -m ruff check .
```

Тесты используют синтетические товары и подменённые ответы OpenAI/ekt.kz.
Они не требуют ключей и не делают внешних запросов. Реальные ключи не входят в тестовые данные.
Зависимости для разработки также описаны в `pyproject.toml` (extra `dev`).

### Ограничения прототипа и следующие шаги

1. Получить источник сертификатов, условия покупки и правила складов.
2. Проверить реальный OpenAI-вызов после настройки ключа; измерить задержку на запросах команды.
3. Уточнить схему характеристик для других категорий и расширить поисковые сценарии.
4. Согласовать контракт демонстрационной корзины и подключить подтверждение на фронтенде;
   получить API и правила для будущей реальной корзины.
5. При публичном развёртывании добавить входной контроль доступа и ограничение затрат/запросов.
   Текущий сервер предназначен для локальной командной разработки, запускается на loopback.
   Сессии находятся в памяти одного процесса, теряются после перезапуска; запускать один worker.
   Поиск сканирует небольшую выборку SQLite; это не индекс полного каталога.
