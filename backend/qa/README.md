# Дополнительный приёмочный gate

Из каталога backend с установленными requirements.lock:

```sh
python -m pytest tests -q --junitxml=regression.xml
python -m pytest qa -v --junitxml=negative.xml
python -m ruff check app tests qa
```

`qa/` запускается явно: стандартный pytest использует `testpaths=["tests"]`.
На commit df8c66d ожидаются 3 падения QA gate: два маршрута со сверхбольшим ID (QA-004)
и повторный импорт устаревшего синтетического fixture (QA-003). Это реальные FAIL,
не xfail/skip и не причина считать приёмку успешной. После исправлений ожидается ноль FAIL.

Не использовать результат регрессии как единственный критерий готовности продукта.
Полная матрица и ручные браузерные результаты: `docs/qa/2026-09-23-report.md`.
Реестр и критерии закрытия: `docs/qa/blockers.md`.

Windows sandbox прогона потребовала обычных прав доступа для создаваемых временных папок
pytest вместо ограниченного mode=0700. Это применялось только в локальном запускателе,
исходники приложения не менялись. В обычном окружении используются команды выше.
